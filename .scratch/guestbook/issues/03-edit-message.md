# 03: 메시지 수정

**What to build:** Author가 자기 Entry의 [수정]을 누르면 현재 메시지가 채워진 입력칸과 글 비밀번호 칸이 그 Entry 안에 펼쳐진다. 비밀번호가 맞으면 메시지가 바뀌고 작성 시각 옆에 "(수정됨)"이 붙으며, 목록 위치·이름·작성 시각은 그대로다. 비밀번호가 틀리면 수정이 거부되고 그 사실이 폼 안에 표시된다. 스펙: [spec.md](../spec.md) (User Stories 19–30)

**Blocked by:** 02 (입력값 검증과 칸별 안내 — 메시지 검증 규칙을 재사용)

**Status:** ready-for-agent

- [x] 도메인 모듈이 `edit(id, { message, password })`를 공개하고 성공 / 검증 오류 / `wrong_password` / `not_found` 중 하나를 돌려준다
- [x] 테스트: 맞는 비밀번호로 수정하면 메시지가 바뀌고 수정됨이 되며, 이름·Created At은 그대로다
- [x] 테스트: 수정한 오래된 Entry가 목록에서 제자리를 지킨다
- [x] 테스트: 틀린 비밀번호는 `wrong_password`이고 Entry는 바뀌지 않는다
- [x] 테스트: 없는 id는 `not_found`
- [x] 테스트: 수정 메시지도 1~500자·공백 제거 규칙을 따른다
- [x] 화면: [수정] → 인라인 폼(현재 메시지 미리 채움), [취소]로 닫힘
- [x] 화면: 성공 시 폼이 닫히고 새 메시지와 "(수정됨)"이 보인다
- [x] 화면: 틀린 비밀번호면 폼 안에 빨간 글씨로 "비밀번호가 일치하지 않습니다."가 뜨고 입력이 유지된다
- [x] 화면: 이미 삭제된 Entry면 "이미 삭제된 글입니다."가 뜨고 목록이 새로 고쳐진다
